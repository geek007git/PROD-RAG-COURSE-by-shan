# Portfolio Projects

The best way to make this project your own is to change the domain, evaluation, or user experience—not merely its colors or name.

## 1. Documentation assistant

Replace arXiv ingestion with public product manuals. Demonstrate document loading, metadata design, cited answers, 20 real evaluation questions, and honest failure examples.

## 2. College knowledge assistant

Index public syllabi, regulations, and department FAQs. Add department, academic-year, and document-type filters. Display policy dates because policies change.

## 3. Support-ticket investigator

Use synthetic support tickets and public documentation. Add product/version filters, PII redaction, feedback buttons, and a “no reliable answer” route.

## 4. Research trend explorer

Keep arXiv but add trend analytics by category, author, and month. Measure whether time and category filters improve retrieval quality.

## 5. RAG evaluation dashboard

Create a versioned dataset of questions, expected sources, and reference answers. Compare BM25, vector, hybrid, and agentic modes using hit-rate@k, mean reciprocal rank, citation correctness, faithfulness, latency, and cache-hit rate.

## 6. Multi-tenant knowledge platform

Add users and isolated collections. Enforce ownership during retrieval, not only in the interface. Include a threat model, authorization tests, audit events, and deletion workflows.

## Portfolio README checklist

Explain:

- the user problem;
- the architecture and why you chose it;
- how to run a small demo;
- what data you used and whether you had permission;
- how you evaluated retrieval and answers;
- known limitations;
- security and privacy decisions;
- what you personally changed;
- screenshots or a short demo video.

Avoid claiming “production-ready” without deployment, security, load, recovery, and monitoring evidence. “Production-style learning project” is accurate and credible.
